## 2. 根因与决策

- **真实根因（实测）**：用户把 **JPEG 改名成 .png**。程序按扩展名分通道 → 用 PNG 解 → 失败；`build_only`「坏图不进系统」在写注册表前中止 → `REGISTRY written=0 / SPI=0`，**指针其实没动**。但旧 UI 把「解码失败」和「加载器拒绝」都印成内部码 `[L1x]`、又不给原因，也没有成败横幅 → 用户无从判断。
- **修在可测的数据层**：状态分类(`RowKind`)、结果横幅(`outcome_*`)都放 `report_model`（无 Win32、可单测），UI 只原样显示；延续 §9.2「GUI/CLI 同构」——CLI 早先就能打印原因，这次把同等信息补到 GUI。
- **伪格式点名**：`png_source` 解码前先嗅魔数，命中 JPEG/GIF/BMP/WEBP/ICO-CUR 报「内容是 X、不是 PNG」，取代含糊的 `stb decode failed`；真 PNG 走原成功分支（单测反向对照防误杀）。
