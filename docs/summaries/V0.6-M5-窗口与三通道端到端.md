## 2. 关键设计决策与偏离

- **D18 子系统（M5 追认，已回写 §3）**：保持 CONSOLE，无参数启动 GUI 时 `GetConsoleWindow()`+`ShowWindow(SW_HIDE)` 隐藏控制台，且仅在交互分支隐藏（截图自检不动调用方控制台）。理由：CLI 的 L3/probe 无人值守 stdout 捕获不能被削弱。代价：纯 GUI 启动一次控制台闪框。
- **偏离 D2（comctl32 v6）**：M5b/M5c 用核心 Win32 控件（user32 `STATIC/EDIT/LISTBOX/BUTTON`），**未接 v6 manifest/rc**，规避本机 `build.bat` 的 rc/manifest 失败面。外观推迟，已进 BACKLOG。功能与判据不受影响（截图证明渲染正常）。
- **实现纠偏（重要，已回写 §11）**：`build_only` 自 M2 起只做 `.cur` 透传；M3/M4 交付的是通道**模块 + 单元测试**，但端到端从没调用它们 —— 且 APP 构建当时不链接 `png_source/svg_source/cur_writer/pixel` 也照样绿，掩盖了「PNG/SVG 其实不可 apply」。`69a7efc` 按扩展名把三通道接入 `build_only`，`tests_m6` 正/负/回归/坏源不写注册表钉死。**教训**：模块测试全绿 ≠ 通道在业务链上可达。
- **确认文案入模型层**：D13「两还原两套文案」做成 `confirm_text_for(GuiAction)` 的纯数据 + 单测断言「标题与正文都必须不同」，UI 只负责显示；避免把「弹窗文案不一样」当成不可验证的口头保证。
