## 2. 关键设计决策与偏离

- **兑现 D2（comctl32 v6），非改 D2**：D2 早已「已定」，V0.6 §2 因规避 rc/manifest 失败面而**推迟**了
  可见性。本批把它落地：manifest 由 rc.exe 打成 `app.res`（RT_MANIFEST 用裸数字 24/id1，避开 rc 对宏的
  版本漂移），链进 app；`InitCommonControlsEx(ICC_STANDARD_CLASSES)` 与 manifest 配对才生效。
  **刻意不加 DPI 感知声明** —— 会改变窗口度量与截图尺寸，属另一条需求，未进 §1/§3，走 BACKLOG，不在本步夹带。
- **皮肤格式 = PNG+SVG 混装**（用户选）：7 槽出 PNG（走 M3）、8 槽出 SVG（走 M4 白名单），`arrow` 同时
  出 `.png` 与 `.svg` —— 把 §5.2「重复认领必须报告、择一必须显式」做成活体冲突（确定性择 `.png`，
  因排序 `skin\arrow.png < skin\arrow.svg`）。生成器 `tools/gen_skin.py` 用纯标准库、同一套矢量坐标同时
  栅格化 PNG 与导出 SVG，与 `tools/gen_png_fixtures.py` 同取向（不信 pip、双通道共享几何）。
- **对角槽反对称**（服务 U19）：`sizenw/sizene` 画成一端实心箭头、一端渐细短尾。此前 M2 真机闭环用
  **对称实心块**，镜像后一模一样、测不出 U19（V0.6 记为方法缺陷）。本批**备好可判读夹具**，但本轮离线，
  **未验镜像本身**。

## 5. 遗留与下一步

**可自动化、不碰真机指针的**
- 逐槽预览面板加「缺哪几槽 / 跳过哪档尺寸」文字说明（§5.2 契约目前只在汇总数字里体现）——承接 V0.6 遗留。
- comctl32 v6 主题化的**像素级 golden** 未进 harness（RT_MANIFEST 在 app exe、GUI 激活上下文无法在无头
  harness 跑）；本批以「构建期 manifest 抽取 + 运行时 OpenThemeData 探针 + 有无 manifest 版像素 diff」
  三条确定性证据替代。

**必须你配合才能推进到 V1.0 的**
- 真素材的**逐槽 L3 端到端**（apply→GetCursorInfo 采样→像素比对→逐位还原）：证明这份皮肤真能换掉屏幕指针。
- U8/U17 的 **hotspot 目测校正闭环** + U19 的**对角镜像目测**：需真机 apply 后人眼看，并写 sidecar 校正。
- 以上跑通即具备打 V1.0 的条件（V0.6 §5 与 DESIGN §11 已把这条列为 M5 后建议顺序）。
