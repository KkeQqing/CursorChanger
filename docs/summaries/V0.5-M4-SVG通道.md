## 3. 两条实测事实（不是假设）

1. **nanosvg 输出是 straight RGBA**。探针：50% 不透明灰圆中心 RGBA = `(126,126,126,127)`；
   若已预乘 R 应为 ~63。故通道层需要预乘一次。该结论由
   `svg_probe_shows_straight_alpha_not_premultiplied` 守住 —— 它变红时**应删掉那次乘法，
   而不是改期望值**。双重预乘不会被「每通道 <= alpha」抓到，只能靠这种数值对照发现。
2. **`url(#id)` 只能按"是否文档内已定义渐变"放行**。实现初版把 `url(` 一律拒绝，
   会误杀渐变填充 —— 而渐变在光标 SVG 里极常见。

## 4. 一条方法论收获

违规制造「从黑名单摘掉 `text`」后**没有任何测试变红**。查下去发现这不是测试失效：
allow-list 的「未知即拒」让该操作在行为上完全无害，**测试不该为它变红**。
真正该钉的是两表关系，于是新增 `svg_guard_tables_are_disjoint_and_unknown_is_denied`：
`allow ∩ block == ∅`、未知元素被拒、黑名单 22 个元素逐个点名可拒（实测 22/22）。
元素层面 block 表只是双保（价值在给出明确拒绝理由）；非它不可的是**属性**类
（`style` / `clip-path` / `mask`），元素白名单管不到属性。

这条区分写进了 §4.3.2，防止后来人把「双保层」当唯一防线去"修"。
