## 2. 关键决策与偏离

- **`.ani` 格式不凭记忆**：Step 侦察先把系统 `aero_busy.ani` 逐字节反解 + 交叉权威规范，纠正了我一度
  「6 个系统 .ani `dwDefaultSpeed` 全 0 → 帧率不在 header」的**误判**（字段贴错标签：第 8 个 DWORD 是
  `iDispRate`，单位 **jiffies(1/60s) 非毫秒**，系统值=3）。writer 按此实现，reader 自测当场抓到并修掉一处
  偏移错。每帧 `icon` 子块 = 一个**完整多尺寸 `.cur`**（直接复用 CurWriter 产物当帧）。
- **诚实边界（动画判据机器抓不到）**：L3 只取单帧，**加载器接受 ≠ 会动画**。透传(U7)与合成(U22)都
  **另做真机 apply + 人眼**才敢标"核销"；验完逐位还原、独立导出比 sha。
- **`allow_upscale` 不开放**：PNG/SVG 通道只做下采样（无放大实现），把 `frames.allow_upscale=true`
  接进 settings 只会让"档位>原生"变 `NoUsableFrame` —— 与其接线一个没用的旋钮，不如按未知 key 拒并记 §10。
  （这是对"设计≠已实现"教训的主动应用。）
- **`.meta` size/hotspot/trim + settings frames.sizes 均"接通可验"**：端到端用 `cur_reader`/`settings_path`
  注入独立核，避免"模块绿≠接通"老坑；settings 用临时路径隔离、不污染其它测试的档位期望。

## 3. §13 未验证项核销情况

- **U7 核销（透传路径）**：`.ani` 经 HKCU+SPI 被 OS 当动画播放，真机肉眼确证。
- **U22 核销**：自造 2 帧 `.ani` `rate=10`（jiffies）apply 到 Arrow，肉眼见 ~6 次/秒交替（=10/60s）。
- 仍**未验**：`U8/U17`（逐槽热点目测）、`U19`（对角是否被 OS 镜像）、U7 的**帧数/尺寸上限具体值**
  （`writer` 只有防溢出的 `max_frames` 硬上限，非 OS 真上限）。这些属 **V1.0** 目测项，不由 M6 关闭。
