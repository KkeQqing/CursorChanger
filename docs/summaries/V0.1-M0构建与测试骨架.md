## 2. 关键设计决策（含对 DESIGN.md 的回写）

- **D18 新增**：`/MT` 静态 CRT + M0–M4 用 CONSOLE 子系统。理由：§11-M0 的尺寸门依赖静态链接（`/MD` 下 15KB 属正常值，门会假红）。实测两个产物 **690176 / 724992 字节**，门取 ≥65536，实测值已回写 U10。
- **D19/D20 新增**：vendor 溯源与镜像拉取通道。实测 `raw.githubusercontent.com` Connection reset、`cdn.jsdelivr.net` schannel 中断、`fastly.jsdelivr.net` 可用。
- **D4 状态由「待实测」改为「前置不成立」**：本机 `cargo`/`rustc`/`rustup` 全 ABSENT，resvg 无法自建。转为 **B-01 待追认**，M0 未依赖它（不阻塞 M1–M3）。
- **版本元数据不放命令行宏**：`/DCS_VERSION=\"...\"` 经 cmd + cl 两层引号处理是纯风险，改由 `src/core/version.h` 单点承载。
- **尺寸门的顺序约束**（新固化）：门只在 cl 退出码 0 之后跑。这使「上一次构建留下的陈旧产物」无法伪造绿灯 —— 与「不做目录删除」并存的前提就是这个顺序，已写进 build.bat 注 4/6。
- **AGENTS 自相矛盾修正**：§3 原写「任一 commit 单独 checkout 都能跑 tests」，与 §7「文档先行」冲突（纯 docs commit 时代码尚不存在）。已收窄为「从 M0 代码 commit 起，feat/fix/test/refactor 单独 checkout 必须绿；纯 docs commit 不受此约束」。
- **AGENTS §7 锚点恢复**：原文被我写成「决策表 → 契约 → 代码」，丢了用户给的「需求文档先行」第一环，已补回为「目标与非目标 → 决策表 → 契约 → 代码」。
- **AGENTS §8 自我纠错**：我给的「`->` 改用 `==>`」这条建议本身仍含重定向符，照做会重现那个 13 字节坑。已改为「ECHO 文案禁用重定向字符，箭头一律改纯字母」。

## 5. 本轮自身犯的错（如实）

1. **第一次破坏性验证是假的**：sabotage 用 inline python 写，被 PS 引号处理打成 SyntaxError，**文件根本没被改**，我却看到「测试仍绿」。若只看绿就收工会把「守卫有效」写成一条无证据的断言。发现方式是重跑后仍红（第二次真破坏）＋回滚那次报错暴露出备份文件从未生成。
2. **inline python 里带转义双引号**在本机 shell 下会静默改坏脚本，两次踩中；正解是先落成脚本文件再跑（AGENTS §8 已含同类教训，此为其一例）。
3. 误以为 `cli.cpp.bak` 存在即等于已备份 —— 实际生成它的那行从未执行。备份要验证，不能推断。
4. 上一轮汇报里把 `DESIGN.md` 行数量成 488（我的 `count('\n')+1` 数法把结尾换行算成一行），Read 工具口径是 487。属计数口径未核对。
5. `main.cpp` 第一版 `printf` 精度参数写重了（6 个实参对 2 个 `%.*s`），且 `cli.h` 的注释承诺了实现里不存在的「动词别名」。两处都在编译前改掉。
