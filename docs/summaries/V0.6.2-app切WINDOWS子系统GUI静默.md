## 2. 关键设计决策与偏离

- **为何必须动子系统**：控制台窗口在进程创建时由 OS 分配，`main()` 里的 `FreeConsole`/`ShowWindow(SW_HIDE)` 都晚于闪框，无法消除；唯一根治是 app 用 `WINDOWS` 子系统（双击/无参启动不分配控制台）。这正是 D18 当年把「闪框」列为可接受代价的根因，本批按用户要求撤销该代价。
- **入口沿用 `main()`**：`/ENTRY:mainCRTStartup` 让 WINDOWS 子系统镜像仍以 `main(int,char**)` 启动，避免为此重写 WinMain（最小改动、不动业务链）。
- **捕获链的真实代价（本轮实测得到，非推断）**：D18 旧文「改 WINDOWS 会牵动捕获链」被量化 ——
  - `Start-Process -Wait -RedirectStandardOutput`：**能**拿到完整输出与 ExitCode（实测 `--version` 85B、ExitCode=0）；
  - PowerShell 用 `&` 调用操作符 + `>` 重定向：对 GUI 子系统子进程 **不等待**，拿到 0 字节（实测）。
  → 结论：功能不受影响（apply/restore/SPI 照常执行）；**自动化捕获 app 的 CLI 输出/退出码必须走 `Start-Process -Wait`**（tests 是 CONSOLE 子系统，其 `tests.bat` 链不受影响）。已写入 `用法.txt` 与本总结。
