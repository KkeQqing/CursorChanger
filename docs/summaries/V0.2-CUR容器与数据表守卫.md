## 2. 关键设计决策（含对 DESIGN 的回写）

- **`Hotspot` 用 core 自有类型**（原 §5.1 写的是 Win32 `POINT`，与 §2「core 不含 windows.h」冲突）。位宽选 `uint16_t`：`validate_spec` 先保证 `width<=256 && x<width`，因而蕴含 `x<=255`，目录项的 WORD 必装得下 —— 论证写在 ir.cpp 注释里，且**检查顺序不可调换**这一点被注释钉住。
- **H10 全透明拒收**进 writer 入口（`writer.reject_fully_transparent`，默认 true）。产出「合法但看不见」的光标比报错严重得多。
- **H11 底向上**归容器层：IR 是 top-down，writer 负责翻转；夹具刻意做成非对称图案，否则行序颠倒不可观察。
- **`min_dir_gap_bytes` 语义纠错**：原 §10 写作「帧数据偏移最小间隔」，实现是「条目总字节下限」。审查指出二者不一致，且旧实现**只登记不写入**，导致 `bytes_in_res > 实写字节`。现按真实语义补齐零字节，并把 §10 描述改对。
- **reader 行距按位深算**：旧实现无条件 `w*4`，对 8/24bpp 第三方光标会把 AND 区整段搬错 —— M2 passthrough 必踩，提前修掉。
- **reader 与 writer 的上限角色分离**：`writer.max_dir_entries=12`（产出侧严格）、`reader.max_entries=64`（校验侧宽松，只用于识别「count 被写坏」），新增 §10 行登记。
- **新增 `WriteStatus::InternalLengthMismatch`**：实写长度与登记长度不符时清空输出并报错，绝不交半坏文件。
- **`.ico` 输入仍不进 v1**（无 hotspot 字段），M1b 的 `WrongType` 判据已能把 type=1 拒掉。

**下一步（M2 / V0.3）**

M2 是**第一个真能天天用的台阶**：`.cur` passthrough 端到端 + 基线三态快照 + HKCU 写入 + `SPI_SETCURSORS` + 两路还原 + L1/L2/L3 自检。开工必须先核销 U1/U2/U12/U14/U16（槽名枚举、SPI 传参、hotspot 字段位置、`biSizeImage`、AND 过填充），因为 M2 的判据本身就是这些假设的实测场。
